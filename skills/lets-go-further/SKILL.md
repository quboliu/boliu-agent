# Let's Go Further
made by quboliu

## Authority and regeneration

- The parent directory is a legacy intake directory named `Let's-Go-Further`.
  Its three supplied files remain untouched. The lowercase `lets-go-further/`
  directory is the canonical production workspace created beneath it.
- `lets-go-further-raw/` contains byte-preserved copies of the supplied English
  EPUB, dual EPUB, and PDF. The English EPUB is the source-text authority; the
  dual EPUB is the translation authority; the PDF is retained as a visual
  comparison reference.
- The source-language Markdown authority is
  `lets-go-further-markdown/chapters/`. It is regenerated by `scripts/convert.py`
  from the English EPUB. The Markdown tree is never hand-patched.
- `scripts/convert.py` also regenerates the three Typst editions from the
  normalized chapter order and the raw dual EPUB translation nodes. It copies
  recovered figures once into the Markdown image tree and then into each edition
  asset tree without recompression.
- The stable semantic source identifiers are the XHTML filenames plus their
  source `id` attributes. No source page number is used as a cross-reference.

## Book-specific conversion rules

- The EPUB XHTML is parsed structurally. English prose, headings, links,
  tables, lists, block quotes, asides, code figures, images, and dagger notes
  are mapped individually; no global markup substitution is allowed.
- The dual EPUB was produced with Immersive Translate wrappers. A wrapper with
  `lang="zh-CN"` is treated as the complete Chinese counterpart of its
  enclosing semantic element. Code, URLs, identifiers, and images remain
  invariant unless the source explicitly contains a translated semantic copy.
- The English EPUB supplies the clean source blocks. The dual EPUB supplies
  Chinese headings, paragraphs, table cells, list items, asides, quotations,
  and note text for the bilingual and Chinese editions.
- Code blocks preserve their language class, title bar, whitespace, and literal
  punctuation. A title bar is rendered as restrained text immediately above the
  code block. The `lang` class is mandatory input to the Typst raw block and may
  not be dropped during conversion.
- Syntax highlighting is a release requirement for every language-tagged code
  block. Use a supported Typst theme or a tested local highlighting mapping;
  probe the installed Typst version before choosing a theme API. Never use
  `theme: none` or an equivalent neutral override in a production edition.
- Verify highlighting in representative Go, shell, SQL, and JSON samples. The
  check must confirm both that language tags survive conversion and that the
  rendered PDF contains visibly colored syntax tokens; a colored title bar or
  code background does not count as syntax highlighting.
- The two source dagger notes are converted into native Typst footnotes. A
  dagger marker inside a source paragraph is never treated as ordinary prose.
- Source figures have no reliable captions in the EPUB and therefore remain
  uncaptained figures. They are placed at 80% of the live width with preserved
  aspect ratio.
- The source image named `cover.png` is the original cover asset and is used
  directly for this private edition. Do not replace it with a newly generated
  publisher cover or an unrelated historical illustration.

## Non-negotiable visual acceptance gates

- Contents pages are a designed book component, not a default Typst outline.
  Before release, explicitly design and review their hierarchy, indentation,
  chapter grouping, spacing, numbering, bilingual alignment, and right-aligned
  page-number column. A contents list with correct entries but default or
  visually weak styling fails acceptance.
- Render and inspect every contents page in every edition, not only the first
  page. Check rasterized pages and extracted text for clipped rows, orphaned
  headings, broken leaders, duplicate page numbers, wrong page references,
  accidental running furniture, blank-page contamination, and malformed
  hierarchy such as `1.0.1`. Contents styling belongs in the template/source
  generator; do not hand-patch generated chapter `.typ` files.
- Code highlighting and contents-page design are blocking release gates. A
  successful Typst compile, zero diagnostics, or a passing generic template
  test cannot waive either gate. In particular, a test that expects all code
  colors to be zero is invalid for this book and must not be treated as proof
  of quality.
- The final release audit records the contents-page review and representative
  highlighted-code review for English, Chinese, and bilingual editions. If a
  language-tagged block has no colored syntax tokens, or if any contents page
  has a visual or reference defect, stop and fix the converter/template before
  regenerating and auditing the PDFs again.

## Scripts and dependencies

- `scripts/convert.py` uses Python 3, the standard library, and `lxml`.
- Regenerate all normalized sources, assets, and edition chapters with:

  ```sh
  python3 .agents/skills/lets-go-further/scripts/convert.py --workspace .
  ```

- The exact edition build command is recorded in each edition's `book.toml`.
  Typst is pinned to the installed `0.15.1` executable for this production
  run. Raw diagnostics are captured under the edition's `output/audit/`.

## Known anomalies and release boundaries

- The dual EPUB contains translation-injection CSS and wrapper markup in every
  XHTML file. The converter deliberately ignores injected CSS and unwraps only
  the semantic translation nodes.
- The source EPUB metadata identifies version `1.24.0` but does not provide a
  separate reproduction permission record for the supplied cover. The source
  cover is therefore marked `rights = "unresolved"` in the contracts. The
  generated PDFs are production proofs, not cleared-for-distribution editions,
  until the user supplies permission or a reproduction-permitted source-cover
  record.
- No source font files were supplied. The project vendors the locally installed
  DejaVu Serif, DejaVu Sans, DejaVu Sans Mono, and Noto Serif CJK SC files; their
  paths and licenses are recorded in the contracts.
