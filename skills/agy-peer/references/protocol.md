# 协议与实现边界

`binding.json` 固定 PID、Linux `/proc/PID/stat` 启动时间、工作目录、TTY 与 agy 当前持有的 `presence/<conversation_id>.lock`。这些是本机实现观察，不是 agy 的稳定公共发现 API。版本或环境变化时先重新验证；不能识别时不猜测会话。

`mailbox.db` 保存消息与事件。消息有递增序号、唯一 ID、双方身份、kind、正文、reply_to、创建/读取/确认时间。SQLite 事务协调并发写入。相同 ID 和相同内容重复投递返回原消息，不再入队；不同内容拒绝。回复必须指向发给自己的来信。ack 只能由收件人执行。

信箱是同 Unix 用户下合作代理之间的约定，并不为两个代理提供独立的安全身份。状态目录 0700，文件 0600；不适用于互不信任用户或外网服务。保持原始消息，不向 Git 同步通信记录。

收件语义为可重读、显式确认。`received_at` 证明工具读到消息；`ack_at` 证明收件人显式接收处理责任。两者都不证明任务成功。处理前崩溃且未 ack 时，下次 receive 会重发；ack 后仍可从 history 恢复。需要端到端重试时沿用消息 ID，先检查是否已经有对应结果，避免重复执行副作用。

终端接入用 `pidfd_open` + `pidfd_getfd` 复制已有 PTY master，仅写入 ASCII 读信命令；用 `TIOCGPTN` 核对终端编号。**不能通过打开 `/proc/PID/fd/FD` 上的 `/dev/ptmx` 来复制 master**，那会新建另一 PTY。不要读取 master 抢走原终端输出，不要更改共享文件描述符的阻塞标记。

本机最初测试中，普通文本加 Enter 成功进入 agy 对话；一次带 bracketed-paste 包装的文本未进入对话。因此只注入短 ASCII 指令，完整文本通过信箱传递。终端空闲和输入框为空需要操作者实际核对，脚本仅验证进程仍持有前台终端，不能自动判断草稿和 UI 弹窗。

推荐协作节奏：Codex 投递任务 → agy 读取并确认 → agy 投递自己的问题/候选意见 → Codex 读取、确认并回答 → agy 根据反馈提交结果。双方监听时，receive 至多每 250ms 检查一次。用户结束回合或代理不再运行工具后，消息仅持久化等待；需要宿主另外提供调度能力才能自动启动新的模型回合。

敏感信息不要放入消息。调试默认检查 message/event ID 和状态，不打印进程环境、内部凭据、整个二进制会话数据库、隐藏推理字段或原始系统调用日志。

2026-10-31 在 Linux/arm64、agy 1.4.11 上完成实际验收：原进程/会话保持不变，agy 收到随机标记后主动询问文章评审范围，Codex 经信箱回答，agy 再确认范围并从上一轮上下文回忆随机标记。8 项脚本测试另外验证了并发投递、编号去重、回复方向、确认权限、未确认来信跨接收端重启保留、等待时到信、过期会话拒绝及目录权限。该记录不覆盖未验证的操作系统/agy 版本，也不证明结束 Codex 回合后的自动唤醒。
