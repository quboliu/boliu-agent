# Validation evidence

This records a CLI integration smoke test, not a guarantee for other accounts
or versions. No local skill installation was part of the test.

- Date: 2026-11-04.
- Environment: Linux aarch64, `codex-cli 0.165.0`, existing ChatGPT login.
- Preflight: local `exec --help` recognized the documented flags;
  `features list` listed `image_generation` as stable and enabled.
- Invocation: `codex exec --json --sandbox workspace-write --enable image_generation`,
  with an isolated temporary working directory, `--skip-git-repo-check`,
  `--ephemeral`, stdin prompt, `--output-schema`, and `--output-last-message`.
  GNU `timeout` supplied a 600-second deadline and 15-second kill grace period.
- Request: one square illustration of an orange paper boat on blue water.
- Outcome: exit 0 in 47 seconds; terminal `turn.completed`; a separate JSON
  success report; generated bytes copied from Codex's generated-image cache
  into the job output directory while preserving the original.
- Independent checks: the reported path stayed inside the job; the file was
  nonempty; Pillow verified and fully decoded a PNG measuring 1254 × 1254;
  format and dimensions matched the report. Visual inspection showed the
  requested boat and water with no text. The report matched the documented
  schema. The event stream exposed no dedicated image-generation event.
- The child initially tried unavailable `python`, then recovered with `python3`.

Untested: reference-image editing, multiple outputs, transparency, other CLI
versions or operating systems, expired authentication, unavailable generation,
forced timeout/kill behavior, interrupted-session recovery, and remote artifact
upload. A configured deadline was exercised only on the successful path.

Raw logs, prompts, credentials, and generated images are excluded from the
repository. The reusable instructions are in `SKILL.md` and `external-tools.md`;
the observations here are evidence for one invocation only.
